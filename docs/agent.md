# Правила параллельной разработки VIctory-NVIDIA

Общее руководство для ChatGPT, Antigravity, Codex CLI и Claude.

## Публикация изменений

- Публикуй каждый законченный логический патч сразу в общей рабочей ветке, не ожидая окончания всех тестов и бенчмарков.
- Перед публикацией проверь изменения и актуальный удалённый SHA. Не перезаписывай чужой код: только fast-forward, без force push.
- Указывай в коммите и комментариях PR #1, какие проверки пройдены, какие ещё не запускались, какие ошибки известны.
- Не выдавай непроверенный патч за стабильную сборку. Рискованные экспериментальные режимы оставляй выключенными по умолчанию.
- Не блокируй остальные задачи ожиданием одной длительной проверки. При подтверждённом зависании заверши только проблемный процесс, сохрани лог и опубликуй промежуточный результат.
- Для сборок, тестов, бенчмарков и git push применяй разумные тайм-ауты; не повторяй уже пройденные проверки того же SHA без причины.

## Координация

- Используй существующие ветки main, dev/nvidia-blackwell и cto/shader-hash-perf. Не создавай дополнительные ветки, worktree или PR без необходимости и согласования.
- Общий PR: https://github.com/ai2n-dev/VIctory-NVIDIA/pull/1.
- ChatGPT: архитектура, GPU, VRAM, CARD_COMPARE и Readback. Antigravity: локальные сборки, аппаратная проверка и исправления совместимости. Codex/Claude: многопоточность и аудит памяти.
- Перед работой проверь изменения других агентов. Не редактируй одновременно одни и те же локальные файлы. Не перезаписывай незакоммиченные изменения.
- Сохраняй авторство и лицензии стороннего кода. Соблюдай docs/asset-policy.md, не публикуй секреты или локальные данные.
- Не объединяй экспериментальную ветку с main до подтверждения сборки и тестов.

Результаты: SHA, проверенный адаптер, тесты, бенчмарки, известные ошибки и следующие шаги. Публикуй по мере готовности, а не одним отчётом в конце.

## Локальный запуск процессов и тестов

- Не открывай дополнительные видимые окна терминала. Используй существующий терминал либо скрытые дочерние процессы с перенаправлением вывода в лог.
- Останавливай только зависшие процессы, созданные тобой, по PID или маркеру в командной строке. Не трогай скачивание игры и другие пользовательские процессы.
- Каждый запуск сборки, теста или скрипта выполняй через watchdog с жёстким тайм-аутом и без автоматического продления. Синтетический selftest стенда ограничен 60 секундами.
- Не перезапускай автоматически неудачный тест. Прочитай лог, найди причину сбоя, исправь её и запусти проверку один раз.
- Если watchdog не остановил задачу, причину исправляй в самом скрипте: любой цикл ожидания должен иметь собственный предел времени, а дочерние процессы теста должны завершаться вместе с ним.

## Обязательный предварительный допуск к локальным GPU-тестам (26.11.2026)

Локальные GPU-тесты NVIDIA, AMD и WARP разрешены автономно, без отдельного разрешения владельца на каждый запуск. Предыдущий общий запрет отменён. Рабочий компьютер владельца не является машиной для воспроизведения системных зависаний. После двух полных зависаний Windows (последнее 13:38 Asia/Almaty) вводится обязательный поэтапный допуск. Причина зависаний не установлена.

1. До запуска изучи diff, точный тест, команды D3D12, владение ресурсами, fence, размеры аллокаций, максимальные dispatch/loop bounds и все ожидания. Не считай WARP на рабочей машине безопасной песочницей.
2. Выполни сборку, Clippy, policy и CPU-only regression tests; не запускай весь workspace локально в качестве предварительной проверки, если он содержит GPU-тесты. Проверь конкретный изменённый SHA на удалённом CI. Если CI не воспроизводит нужный путь, добавь ограниченный удалённый regression или используй отдельную тестовую машину; не подменяй аппаратную проверку заявлением о зелёном CI.
3. Проверь журнал предыдущих запусков, свободную RAM/VRAM/диск, активные процессы и состояние адаптера. Один агент и один аппаратный тест на весь компьютер, включая другие клоны. Запиши SHA, имя теста, адаптер, режим, PID, старт и лог до отправки первой GPU-команды. Сохраняй журнал вне git, чтобы он переживал аварийную перезагрузку.
4. Предварительный тест: сначала проверенный короткий DXGI/device smoke, затем минимальная операция с одним маленьким буфером, ограниченным dispatch и fence timeout, без тяжёлой сцены, Debug Layer или экспериментальных флагов. Не расширяй нагрузку до успешного завершения каждого этапа и проверки новых ошибок системы.
5. Запускай один конкретный тест с --exact --test-threads=1, через watchdog, с отдельным коротким лимитом. Для повторного исполнения, многопоточности, high-VRAM, Debug Layer и stress необходима предварительная проверка соответствующего сценария вне рабочего ноутбука. Никогда не используй циклы 10x/15x и пакетные прогоны для воспроизведения известного системного сбоя.
6. При timeout, device removed, TDR, WHEA, аварии, полном зависании или незавершённой записи после перезагрузки — не запускай этот тест и его эквиваленты повторно на рабочем ноутбуке. Сохрани логи, исследуй без нагрузки, исправь причину и проверь исправление удалённо/на отдельной машине. Разблокировать подозрительный путь можно автономно только после документированных результатов, подтверждающих исправление именно подозрительного сценария на изолированной системе; если это невозможно, оставь его в карантине, продолжай независимые задачи. Обычные не связанные с инцидентом тесты допустимы после preflight, если нет признаков общей проблемы системы.
7. Не меняй TDR, драйверы, BIOS, режим питания, реестр или защиту системы без отдельного разрешения. Не трогай пользовательские процессы. Watchdog не защищает от зависания ядра/драйвера; зелёный smoke и CI уменьшают риск, но не гарантируют отсутствие зависаний.

Техническое применение: все локальные агенты должны использовать единый межпроцессный lock и устойчивый к перезагрузке журнал допуска, расположенные вне репозитория и общие для всех клонов. Не запускать GPU-тест напрямую в обход допуска. Пока общий запускатель не установлен и не проверен CPU-only, аппаратные задания не начинать; продолжать разработку и удалённый CI. Обновить локальный md/agent.md, не перезаписывая чужие изменения.
